# Логика работы OCR desktop-приложения

## Целевой сценарий (касса веревочного парка)

### Поток данных
- **Необработанные сканы**: `scans/inbox`
- **Успешно обработанные**: `scans/processed`
- **Ошибки обработки**: `scans/failed`
- **OCR-выгрузки батчей**: `exports/ocr_batch_YYYYMMDD_HHMMSS.csv`
- **Выгрузки только новых клиентов для CRM**: `exports/crm_new_YYYYMMDD_HHMMSS.csv`

### Принцип "обработано / не обработано"
1. OCR берёт файлы **только** из `scans/inbox`.
2. После завершения:
   - при успехе файл переносится в `scans/processed`;
   - при ошибке — в `scans/failed`.
3. Для аудита хранится реестр `app_state/scan_registry.json` с полями:
   - `sha256`, `filename`, `processed_at`, `output_csv`, `status`.

### Как исключаются дубли в CRM
1. При экспорте в CRM читается последний OCR-батч.
2. По каждой строке формируется fingerprint:
   - `LAST_NAME|FIRST_NAME|PATRONYMIC|BIRTH_DATE|PHONE` (в нормализованном виде).
3. Fingerprint сверяется с `app_state/crm_sent_registry.json`.
4. Если fingerprint уже есть — запись пропускается.
5. Если нет — запись попадает в `crm_new_*.csv` и добавляется в реестр отправленных.

> Это защищает от повторной отправки одного и того же клиента при повторной обработке сканов или переэкспорте.

## Сохранённый функционал из текущей системы
1. **Коррекция координат ячеек**: кнопка запускает `scripts/02_configurator.py`.
2. **Коррекция распознанных бланков / dataset_review**: кнопка запускает `scripts/05_review_scans.py`.
3. **Инвертирование dataset_review**: кнопка запускает `invert_dataset_review.py`.
4. **Дообучение с кастомными EPOCHS**: поле ввода + запуск `scripts/train_model.py --epochs N`.
5. **Открытие папок**: `dataset_external`, `dataset_review`, `scans` из интерфейса.
6. **OCR необработанных сканов в CSV**: кнопка обработки `scans/inbox`.

## Рекомендации для внедрения на кассе
- В настройках сканера указать папку сохранения: `.../OCR_project/scans/inbox`.
- Добавить в инструкцию кассира 3 шага: **Импорт/сканирование → OCR → Экспорт в CRM**.
- Раз в день администратор просматривает `scans/failed`.
- Раз в неделю оператор ML делает review + fine-tuning для роста качества.
